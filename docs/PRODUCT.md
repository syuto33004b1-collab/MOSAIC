## 誰のための道具か

MOSAIC は**社内利用の自社の道具**です。主たる利用者は、**アサインと評価を行う人**です。管理職、プロジェクトマネージャー（PM）、リーダーがこれに当たり、全社のアサインを管轄する重役も含みます。アサインを管理する人は1人ではありません（[#598](https://github.com/syuto33004b1-collab/MOSAIC/issues/598)）。

- **やること**
  - 案件に必要な人を探し、適任を選び、アサインを管理する
  - その人の経歴・スキル・経験・評価を一か所で見て、判断材料にする
  - 案件や成果のあとに、その人について良い面も課題も残す。契約の更新や処遇を決めるときの判断材料になる
- **最終的な判断は人がする。** MOSAIC は判断材料を揃えるための道具であり、自動では決めない
- **全社を見る使い方も含む。** 重役が全社の状態を見て、どこが遊休でどこが過負荷かを判断する使い方（[#326](https://github.com/syuto33004b1-collab/MOSAIC/issues/326)）はその一部です。判断の射程は、週単位ではなく四半期から年単位になりえます
- **利益の出どころ**: 適任を早く正しく選べること、遊休と過負荷が減ること、人についての判断に材料が揃うこと

参照できる人の範囲は、制限を設定しない限り全社です。権限モデルでは `owner` は参照範囲の制限対象に入りません。`admin` / `planner` / `viewer` に付ける `personScope` の既定は全社（`organization`）で、部門サブツリー・部門・本人のみに絞れます。絞った設定は、主たる利用者である PM やリーダー自身にも掛かります。

評価や取消の理由のような**人についての判断は、全員には見せません。** 誰が読めるかは [`docs/SECURITY.md`](SECURITY.md) に置きます。

## なぜを残す

**判断を伴う変更に理由を残すことは、この道具の重要機能です**（[#598](https://github.com/syuto33004b1-collab/MOSAIC/issues/598)）。アサインの取消、人への評価など、後から「なぜそうしたのか」を問われうる変更が対象です。理由は、判断を見直すときや、人についての判断（評価・処遇）をするときの材料になります。

- **判断を伴う操作を足すときは、理由の置き場を一緒に設計する。** 取り消す、評価する、外す、といった操作が該当します
- **理由は、その変更を見られる人より広くは見せない**
- **理由や日時が記録されていない過去の変更は「記録なし」と示し、推測で埋めない**

## 既に決まった非目標

判断済みのものだけを書きます。出典が辿れないものはここに入れません。

| 非目標 | 出典 |
| --- | --- |
| 解除できない共有ビュー・不透明 ID・失効付きの**ライブ社外共有** | [#148](https://github.com/syuto33004b1-collab/MOSAIC/issues/148) の利用者判断。社外提出はファイル書き出しとし、リンクの社外共有ページは作らない |
| 履歴書・職務経歴書の様式 | [#326](https://github.com/syuto33004b1-collab/MOSAIC/issues/326)。社外提案用の文書であり、社内では不要（スキルシートは別に扱う） |
| 提案画面の表示モードとしての氏名秘匿（候補A ラベル） | [#332](https://github.com/syuto33004b1-collab/MOSAIC/issues/332)。社内の決裁者が使う画面であり、氏名を隠す要件ではない（[#326](https://github.com/syuto33004b1-collab/MOSAIC/issues/326)）。参照範囲の制限（`personScope`）は権限モデルの機能であり別物 |
| 価格設計・ランディング・セルフサーブ登録 | [#326](https://github.com/syuto33004b1-collab/MOSAIC/issues/326)。自社の道具で確定している |
| 工数実績（タイムシート） | [#330](https://github.com/syuto33004b1-collab/MOSAIC/issues/330)。計画側のコストで足り、事後の集計は会計・勤怠側が持つ |
| 対外請求・請求単価・売上・粗利・見積・請求書 | [#330](https://github.com/syuto33004b1-collab/MOSAIC/issues/330)。販売・会計の領域 |

語の区別: **対外請求単価**は上表の非目標です。**社内の計画原価**（メンバーの月額原価や遊休コストの集計）は非目標ではありません。

この表に無いものは非目標ではありません。未決は Issue で扱います。評価を評価された本人へ開示することも、非目標ではなく未決です（[#598](https://github.com/syuto33004b1-collab/MOSAIC/issues/598)）。

## 機能を足すときの判断基準

競合や参考サービスを見て候補を挙げるやり方は続けて構いません。足すかどうかを決めるときは、次を使います。

1. **アサインと評価を行う人が、適任を早く正しく選べるようになるか。判断材料が増えるか。** 遊休と過負荷が減ることも含みます
2. **手続き**: その機能が無いとその人たちは何を見落とすか、を1行で書けない提案は起票しない
3. **判断を伴う操作なら、なぜを残せるか**（[なぜを残す](#なぜを残す)）
4. 操作画面の改善は、その人たちの日々の作業を速くするなら採用する

機能の優先順位は方針ではなく Issue とマイルストーンの側で持ちます。
